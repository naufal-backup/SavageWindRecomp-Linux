**Alpha 3: the Linux build is now built and released automatically.** The game itself is
unchanged from Alpha 2 (upstream's build): *The Legend of Zelda: Breath of the Wild* 1.8.2 through
the opening in the Shrine of Resurrection and out onto the Great Plateau at 60 fps, with sound,
voices, the HUD, saving and loading. Nobody has played past the Great Plateau yet, so expect bugs
or crashes further on.

> [!IMPORTANT]
> **No game files are included.** You need your own legally obtained copy of the game, updated to
> **version 1.8.2**, extracted from **your own** Nintendo Switch. Savage Wind provides no game
> files, keys, firmware, dumping or decryption tools, or instructions to obtain any of them, and
> it never decrypts anything. The game code is recompiled on your machine, from your files, for
> your own use only: don't share it. This is a fan project, not affiliated with or endorsed by
> Nintendo.

## Download

`Savage_Wind-0.2.0-alpha.2-x86_64.AppImage` (verify it against `SHA256SUMS`). The file name still
says alpha.2 because the version string in the source has not moved yet; the game and runtime
inside are the same code as this tag.

## What changed since Alpha 2

- **Built in an Arch Linux container**, `archlinux:base-devel`, with the distribution's own
  toolchain (clang 23, lld, llvm): no PPA, no `python3.12`, just `pacman -Syu`. SDL3, an LGPL-only
  FFmpeg, shaderc and the Vulkan / VMA headers are still built from the pinned sources in
  `tools/linux/build_deps.sh`, never taken from the distribution.
- **Released automatically**: `.github/workflows/release-linux.yml` builds the AppImage on a `v*`
  tag (or by hand) and creates this release with its changelog and checksums. A run takes about
  8-11 minutes.
- **`make appimage-arch`** / `make appimage BASE=arch` builds the same AppImage locally in podman;
  `make appimage` still builds the Ubuntu 22.04 one.
- **The build scripts are executable in git again.** `tools/linux/*.sh` and `tools/fetch_zig.sh`
  were committed as 100644, so calling them directly - a CI job, or the steps in `docs/linux.md` -
  stopped with `Permission denied`; `make appimage` never noticed because podman runs them as an
  argument.
- `tools/linux/gen_helper.sh` takes its interpreter from `PY` (Arch has no `python3.12`).
- `docs/BUILD-linux-arch.md` describes both build images and the glibc floor.

## Running it

    chmod +x Savage_Wind-0.2.0-alpha.2-x86_64.AppImage
    ./Savage_Wind-0.2.0-alpha.2-x86_64.AppImage

The start screen asks for the folder with your own game files (`exefs/` and `romfs/`, version
1.8.2) and sets them up once: it builds the data image and recompiles the game code on your
machine, about 40 minutes with a 12-thread CPU. From then on it goes straight into the game.
`--config`, or the **Savage Wind Configuration** desktop action, opens the configuration screen.

Everything the app writes lives in `~/.local/share/savagewind`; `SAVAGEWIND_DATA_ROOT=<dir>` uses
another folder. Log: `~/.local/share/savagewind/savagewind.log`.

## Requirements

- A **recent distribution**: Arch, CachyOS, Fedora rawhide, and future releases. The binary in this
  AppImage requires **GLIBC_2.43**; it does not run on Ubuntu 24.04 or Debian 13. Build it yourself
  with `make appimage` (Ubuntu 22.04 image, glibc 2.35+) for those.
- An x86-64 CPU with AVX2, and a GPU with Vulkan 1.3.
- About 35 GB of free disk space for the game files and the game code build.

Not bundled: glibc, libstdc++, the Vulkan loader and the GPU drivers, which are always the system's.
SDL3, FFmpeg (LGPL only), shaderc and the start screen font are bundled.

## Known issues

- Only the Shrine of Resurrection and the Great Plateau have been played.
- DLC isn't supported. Only game version 1.8.2 is accepted.
- Stuttering, distant LOD problems and other graphics issues are tracked upstream in
  [Revivedx/SavageWindRecomp issues](https://github.com/Revivedx/SavageWindRecomp/issues).
